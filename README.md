## 项目定位

亿企工场 WMS 是亿企工场的仓储管理业务应用，目标是围绕仓库、库区、库位、物料、批次/序列号和库存状态，连接入库、库内、出库与盘点调整，形成账实一致、任务可追踪的仓储作业闭环。

本仓只维护 WMS 页面、业务 API、领域类型与仓储执行规则。认证、租户、菜单、权限、布局、路由、公共组件、Store 和 Supabase 公共客户端由 [`art-supabase-pro`](https://gitee.com/wangyanghub/art-supabase-pro) 统一提供；仓库、库位和物料的统一身份由 MDM 及其权威来源提供。

WMS 已接入仓储运营工作台、库存批次与流水、收料入库、领料申请、出入库、退货、调拨、盘点、调整和序列号追溯。页面按租户及角色授权，库存过账由数据库受控函数执行。预约、波次拣选、复核与装车交接仍需独立业务契约，不应把已有的直接出库视为这些环节已完成。

## 单据批量删除契约（2026-10-08）

- 初始库存、期初销售出库/退货、期初采购入库/退货，以及共用工作区中的普通销售/采购、其他出入库、委外加工、生产收发、调拨申请、盘盈/盘亏和出库申请，均在按单据与按明细视图提供勾选及批量删除。复用主平台 `useDocumentBulkDelete`，使用各页面已有的 `Delete` 权限与受控删除接口。
- 按明细勾选删除所属整张单据及全部明细，不是局部删行；确认框列示单据数量及编号，同一单据去重。只允许可维护的暂存单，生产单据还要求未办理；已提交、已审核、初始化封账等限制继续由服务端执行。
- 确认前通过 `MasterDataDeleteGuard` 检查全部待删除单据。引用检查失败或无权限时停止；并发删除被拒绝后重新检查剩余单据引用。逐张调用受控接口，遇到失败立即停止，已成功部分刷新并明确提示，不把部分成功描述为整批成功。
- 切换视图与刷新清空勾选，删除过程中阻止重复提交。直接调拨、分步调拨、库存调整、组装/拆卸没有现成的单据删除接口；盘点方案采用取消并保留实盘记录。这些已发生库存业务的记录不接入暂存单删除。
- 主平台 `tests/e2e/wms-bulk-delete.spec.ts` 使用隔离模拟数据覆盖五类初始化单据的两种视图、去重、确认前引用校验、引用阻断、检查失败、混选非暂存单、取消、只读权限及部分失败。线上业务记录不用于删除回归。

验收：主平台和 WMS 类型检查、修改文件 ESLint、UI、权限及复用审计通过。五类初始化单据的两种视图、六项删除防护及 1280px 专注模式共 17 个独立浏览器场景通过；采购场景补齐父单据分页模拟响应后单独重跑通过。已检查确认框及选择栏截图，专注模式可通过按钮及 Esc 退出。

## 库存查询契约

主平台 `sys_menu` 的「库存查询」位于「生产出入库」之前，依次提供即时库存、库存流水、库存台账和物料收发明细表。四页共用 `src/views/inventory-trace/shared/inventory-report-workspace.vue`，表格通过只读 `public.wms_inventory_report_secure` 获取分页、总数和仓储位置计数。服务端函数是 `SECURITY INVOKER`，仅向 `authenticated` 授予执行权限；表及关联主数据继续受各自 RLS 约束。前端传入的租户 ID 只是缩小读取范围，不负责授权。

- 即时库存按批次正数当前余额列示；日期区间筛选该批次最近一次库存变动时间。左侧为仓库→库区→库位。
- 库存流水与物料收发明细表按不可变库存流水的业务日期列示；一次调拨在来源和目标批次各有一条出入方向记录。项目全称按该笔业务的项目归属筛选。左侧为仓库→库区。
- 库存台账按批次和仓储位置汇总日期区间。`期初 + 入库 - 出库 = 结存`；无开始或结束日期时，对应期间边界延伸至首笔流水或当前余额。
- 「汇总值」默认选库存数量和基本数量，可增选两个辅助数量；基本及辅助数量由 MDM 物料的单位换算比率计算。未配置有效换算时显示空值，不推测单位关系。
- 项目调拨仍由即时库存的单行受控操作进入，过账权限和数据校验保持在原有服务端边界。

2026-09-27 验证：四类报表的 `navigation` 计数与未选仓储位置时的记录总数一致；指定期间的台账逐行满足期初、入库、出库、结存的勾稽关系；无匹配条件返回空数据和空位置计数。已分别验证普通用户本租户、伪造跨租户请求头、平台超级用户全部租户及指定租户的读取范围。WMS 类型检查、ESLint、边界审计和构建，以及主平台 UI 审计通过。本地 Chrome 注入只读模拟响应后检查了四页渲染、库位筛选、分组表头、加载/空结果/错误/重试状态和 1440px/390px 整页溢出。浏览器会话过期且当前环境对 Supabase Auth 请求返回连接重置，真实登录页面的视觉复核需在网络恢复后执行。

## 初始化账务与库存职责（2026-10-08）

- 初始库存单按物料、仓库、库位、批次和序列号登记实存余额；审核写入期初库存及成本，库存台账列为期初结存。批次管理物料必须填写历史批次，同一库存粒度不得重复初始化。
- 期初销售出库、销售退货、采购入库、采购退货仅记录未结清往来。审核不生成库存收发，退货表单以红色正数录入及查看，列表以红色负数列示。
- 已审核期初往来单可下推独立 `wms_initial_obligation` 明细账：销售形成应收，采购形成暂估应付，退货冲减对应余额。来源单唯一约束防止重复下推；该账不自动生成财务总账凭证。
- 「结束初始化」按组织提供「初始化对账表」，分别核对库存期初成本和往来金额。未结清往来只是历史业务的一部分，其数量净额不能作为仓库实存余额的强制等式。
- 结束初始化后冻结期初单据及行。正常收发必须在初始化结束后执行，业务日期不得早于启用日期；期初单据不得晚于启用日期。状态操作及直接表写入均由服务端校验，期间锁避免初始化与正式业务混入。
- 数据库修改前的恢复快照位于私有表 `app_private.wms_initialization_fix_backup_20261008`。历史期初采购误入库存的四笔共 430 数量保留原流水，并以 `initialization_correction` 修正库存；正常报表排除这些初始化历史收发。一次验证脚本遗漏回滚造成的测试流水及临时封账已精确恢复，恢复记录保存在同一私有快照，启用审计仍保留。
- 回归证据位于主平台 `supabase/tests/wms_initialization_separation_test.sql` 和 `tests/e2e/wms-opening-return.spec.ts`、`wms-initialization-reconciliation.spec.ts`、`wms-material-category-selector.spec.ts`；数据库回归整体使用 `BEGIN` / `ROLLBACK`。

验收结果：初始化隔离、库存期初展示、批次租户隔离数据库回归通过；主平台、WMS、SCM 完整类型检查、主平台聚焦类型检查、ESLint、样式、UI 与共享复用审计通过。Chrome 验证了两类期初退货、分类及子分类选择、对账表的失败重试／空态／手机与深色展示，以及三种权限的结束初始化操作。超级管理员完整应用首次冷启动超时，缓存就绪后复跑通过。主平台全量单元回归 412/413 通过，独立模块公共资源构建子进程两次达到 60 秒超时，未修改该测试或扩大其超时时间。

## 目标作业闭环

```text
到货预约
  → 收货与数量交接
  → 上架与库存形成
  → 补货 / 移库 / 盘点
  → 波次 / 拣选 / 复核
  → 发运与装车交接
  → 库存流水、批次与任务追溯
```

## 跨模块办理前置条件

- MDM：先启用物料和仓库，设置仓库所属组织及业务应用范围。工单领料仓库必须包含「拣货」，且仓库类型要与工单类型允许的领料仓库类型一致；启用库位的仓库还需维护可用库位。
- SCM 采购：采购收料明细下推收料入库草稿，WMS 在草稿中核对并确认；来源单号、数量及租户关系由服务端校验。
- MES 生产：已下达工单可发起领料申请；审核后按批次分次出库并核销申请余额。完工入库以已审核报工数量为上限。
- SCM 销售：已提交的发货通知单可进入销售出库；WMS 按通知行与剩余数量过账。TMS 运单与装车交接尚无同一来源单据契约，不能以 WMS 出库代替承运交接。

## 后续建设重点

2. 与 TMS 建立来源单据、交接回执、异常与幂等冲销契约。
3. 继续扩展 MES 退料和跨环节批次/序列追溯。
4. 基于真实库存流水完善预警、周转、库容与作业效率分析。

## 与主仓协作

WMS 业务修改在本仓提交并推送，随后在主仓更新 `modules/art-supabase-wms` 子模块指针。跨模块数据通过用途明确、字段最小化、租户隔离的 API/RPC 契约读取；本仓不直接导入 MDM、MES、TMS 或其他业务仓源码。

## 安全原则

- 普通用户只能访问当前租户及授权仓库范围内的数据。
- 收货、上架、移库、冻结、解冻、拣选、复核、发运和盘点调整必须拆分权限并由服务端校验。
- 库存变化必须由业务单据和不可变流水驱动，不能通过前端直接修改余额。
- 页面可见不代表后端授权，数据库 RLS、RPC、库存约束与幂等规则是最终安全边界。
