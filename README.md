## 项目定位

Art Supabase WMS 是 Art Supabase Pro 的仓储管理业务应用，目标是围绕仓库、库区、库位、物料、批次/序列号和库存状态，连接入库、库内、出库与盘点调整，形成账实一致、任务可追踪的仓储作业闭环。

本仓只维护 WMS 页面、业务 API、领域类型与仓储执行规则。认证、租户、菜单、权限、布局、路由、公共组件、Store 和 Supabase 公共客户端由 [`art-supabase-pro`](https://gitee.com/wangyanghub/art-supabase-pro) 统一提供；仓库、库位和物料的统一身份由 MDM 及其权威来源提供。

## 当前状态

WMS 已接入仓储运营工作台、库存批次与流水、收料入库、领料申请、出入库、退货、调拨、盘点、调整和序列号追溯。页面按租户及角色授权，库存过账由数据库受控函数执行。预约、波次拣选、复核与装车交接仍需独立业务契约，不应把已有的直接出库视为这些环节已完成。

| 建设领域 | 当前状态 | 目标能力                                             |
| -------- | -------- | ---------------------------------------------------- |
| 应用底座 | 已完成   | 独立运行、平台装载、统一主题导航与角色访问           |
| 仓网基础 | 已接入 MDM | 仓库、库区、库位、物料及仓库业务范围                 |
| 库存台账 | 已接入     | 批次、序列号、预留、库存流水与即时库存               |
| 作业执行 | 部分完成   | 收料入库、领料、出入库、退货、调拨、盘点和调整已接入 |
| 运营优化 | 部分完成   | 项目仓储复盘已接入；波次、复核和装车交接待建设       |

## 目标作业闭环

```text
到货预约
  → 收货与数量交接
  → 上架与库存形成
  → 补货 / 移库 / 盘点
  → 波次 / 拣选 / 复核
  → 发运与装车交接
  → 库存流水、批次与任务追溯
```

## 跨模块办理前置条件

- MDM：先启用物料和仓库，设置仓库所属组织及业务应用范围。工单领料仓库必须包含「拣货」，且仓库类型要与工单类型允许的领料仓库类型一致；启用库位的仓库还需维护可用库位。
- SCM 采购：采购收料明细下推收料入库草稿，WMS 在草稿中核对并确认；来源单号、数量及租户关系由服务端校验。
- MES 生产：已下达工单可发起领料申请；审核后按批次分次出库并核销申请余额。完工入库以已审核报工数量为上限。
- SCM 销售：已提交的发货通知单可进入销售出库；WMS 按通知行与剩余数量过账。TMS 运单与装车交接尚无同一来源单据契约，不能以 WMS 出库代替承运交接。

## 后续建设重点

1. 补全到货预约、波次拣选、复核与装车交接的业务单据和状态机。
2. 与 TMS 建立来源单据、交接回执、异常与幂等冲销契约。
3. 继续扩展 MES 退料和跨环节批次/序列追溯。
4. 基于真实库存流水完善预警、周转、库容与作业效率分析。

## 独立运行

环境要求：Node.js `>= 22.0.0`、pnpm `>= 11.9.0`。

```powershell
pnpm install
pnpm dev
```

默认访问 `http://localhost:3018`。

```powershell
pnpm check
pnpm build
pnpm preview
```

生产构建输出到 `docs/`，默认公共路径为 `/art-supabase-wms/`，可作为 Pages 发布目录。

## 与主仓协作

WMS 业务修改在本仓提交并推送，随后在主仓更新 `modules/art-supabase-wms` 子模块指针。跨模块数据通过用途明确、字段最小化、租户隔离的 API/RPC 契约读取；本仓不直接导入 MDM、MES、TMS 或其他业务仓源码。

## 安全原则

- 普通用户只能访问当前租户及授权仓库范围内的数据。
- 收货、上架、移库、冻结、解冻、拣选、复核、发运和盘点调整必须拆分权限并由服务端校验。
- 库存变化必须由业务单据和不可变流水驱动，不能通过前端直接修改余额。
- 页面可见不代表后端授权，数据库 RLS、RPC、库存约束与幂等规则是最终安全边界。
